# Configuration Reference

This project runs as a standalone Node.js server. All settings are controlled by environment variables in `.env`.

## Required Environment Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `TG_APP_ID` | Telegram API ID from `my.telegram.org` | `123456` |
| `TG_APP_HASH` | Telegram API hash from `my.telegram.org` | `abcdef123456...` |
| `TG_SESSION` | MTProto session string generated by `npm run login` | `1abc...` |
| `TG_GROUP_ID` | Telegram supergroup or channel used to store chunks | `-1001234567890` |
| `S3_ADMIN_KEY` | Admin S3 access key | `admin` |
| `S3_ADMIN_SECRET` | Admin S3 secret key | `adminsecret` |

## Optional Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `3000` | HTTP server port |
| `S3_REGION` | `us-east-1` | S3 region reported by the server |
| `CHUNK_SIZE` | `10485760` | Chunk size in bytes for CAS uploads |
| `DATABASE_PATH` | `./data/tg-s3.db` | SQLite metadata database path |
| `DB_PATH` | `./data/tg-s3.db` | Alias used by the app |
| `CACHE_DIR` | `./data/cache` | Local cache directory for hot chunks |
| `TEMP_DIR` | `./data/temp` | Temporary staging directory |
| `CACHE_RETENTION_DAYS` | `7` | Local cache retention period |
| `LEAVE_IN_CACHE` | `false` | Keep cached content after the normal retention window |
| `HOT_CACHE_DAILY_THRESHOLD` | `10` | Daily hot-cache threshold |

## Local Storage Layout

The current implementation keeps metadata and cache on the local machine:

- SQLite metadata database: `./data/tg-s3.db`
- Local chunk cache: `./data/cache`
- Temporary upload working directory: `./data/temp`

## Telegram Setup

1. Go to https://my.telegram.org and create an app.
2. Copy the `api_id` and `api_hash` values into `.env`.
3. Run `npm run login` to generate the MTProto session string.
4. Add the generated `TG_SESSION` value to `.env`.
5. Specify the Telegram supergroup or channel ID in `TG_GROUP_ID`.

## Security Notes

- S3 credentials are stored in the local SQLite database and validated with SigV4 and presigned URL checks.
- The app is designed for a single-owner environment and does not implement bucket policies or multi-tenant access control.
- Keep `.env` out of source control and restrict file system access to the local machine running TG-S3.

## Rate Limits and Constraints

The practical limits are driven by Telegram and the local runtime:

| Resource | Limit |
|----------|-------|
| Telegram Bot API file download | 20 MB (default) / 2 GB with local Bot API support |
| Telegram Bot API file upload | 20 MB (default) / 2 GB with local Bot API support |
| Local cache size | Depends on the machine filesystem |
| Metadata database | Depends on local disk and SQLite performance |

This project is intentionally English-only and does not ship multilingual runtime or deployment paths.
